# Apexatix Pro Bot

## Market data providers

All requested asset candles use Twelve Data first, Finnhub second, and the open-source Python `yfinance` package as a tertiary fallback. If both keyed providers fail, the Node market-data endpoint calls the Python `/api/yfinance` function, which retrieves 15-minute Yahoo Finance history. Slash-separated FX/metals symbols map to Yahoo's `BASEQUOTE=X` tickers (for example `EURUSD=X`); crypto symbols map to `BASE-QUOTE` (for example `BTC-USD`); symbols without a slash are used as Yahoo tickers directly. Yahoo availability and intraday history limits vary by instrument; an unavailable Yahoo ticker is reported as an error rather than substituted with a different instrument. Fallback data cannot be independently verified, so the source status remains unavailable and the conservative strategy will continue to HOLD.

When Twelve Data succeeds and `FINNHUB_API_KEY` is configured, Finnhub is queried as an independent comparison source. If Twelve Data fails, Finnhub may serve the candles; if both keyed providers fail, yfinance is tried for the same requested symbol. Configure `TWELVE_DATA_API_KEY` and `FINNHUB_API_KEY` as server-side environment variables for local development and deployment. `requirements.txt` installs yfinance for the Python function. Do not expose provider keys in browser code.

## Market scanning and alerts

The dashboard defaults to XAU/USD, BTC/USD, EUR/USD, and AUD/USD; silver is not in the default watchlist, but users can add assets manually. It refreshes closed-candle market data while open and auto-scan is enabled. Trend direction is determined by a two-of-three vote from EMA9/EMA21, MACD versus its signal, and RSI above/below 50; requiring all three to agree could leave a sustained trend unrecognized when RSI lagged. The default strategy and scheduled scanner use that rule for the 45-minute regime and entry checks, then require at least two of the 15m, 30m, and 45m trends to align. This produces BUY setups only in a confirmed bullish trend and SELL setups only in a confirmed bearish trend. Each dashboard card now labels its detected 45m trend independently of whether there is a complete entry setup. The optional **Trend + Dual-TF RSI Confluence** strategy adds a pullback requirement: the 45m trend and selected entry-timeframe EMA/MACD must agree, then 15m and 30m RSI must both confirm an oversold pullback (≤30 and ≤38) for BUY or overbought pullback (≥70 and ≥62) for SELL.

The **Conservative Day-Trade Pullback** option applies stricter entry gates: both feeds must verify the same completed candle, volume data must be available and not unusually low, the 30m and 45m two-of-three EMA/MACD/RSI trend votes must agree, the selected entry timeframe's EMA/MACD must confirm that direction, and 15m RSI must reset to 40–<50 for BUY or >50–60 for SELL. The general Dual-TF RSI, EMA/MACD, and Bollinger/RSI strategies also require the signal direction to agree with the confirmed 45m trend, preventing counter-trend BUYs in bearish regimes and counter-trend SELLs in bullish regimes. A bearish 45m trend can produce SELL setups when the selected strategy's own entry conditions confirm; if any required trend or entry signal is missing or conflicts, the result is an explanatory HOLD. While the dashboard is open, it checks market data every minute and can issue a deduplicated browser **WATCH** notification when the 45m direction is established and the 15m EMA or MACD is converging toward a possible entry. A WATCH is an early heads-up, not a trade signal; BUY/SELL still requires the full strategy rules. The GitHub Actions workflow calls `/api/bot` every five minutes; when `DISCORD_WEBHOOK_URL` is configured, it sends confirmed BUY/SELL and recent WATCH events only when the latest closed candle is no more than five minutes old, avoiding stale reports and repeated alerts for the same candle. Configure repository secrets `VERCEL_URL` and `CRON_SECRET` for the scheduled workflow. BUY/SELL signals use the existing ATR-based invalidation reference (normally 1.5× ATR, refined by nearby support/resistance where justified) and a 2:1 target; this does not calculate position size or guarantee limited losses. Alerts include a rationale, timestamp, and market/indicator snapshot.

When both feeds return candles, a same-candle price disagreement above 0.5% for traditional markets or 1% for crypto suppresses entries. Source verification and provider details continue to inform signal validation but are omitted from dashboard cards and summaries.

Signals are held during quiet volatility (ATR below 0.02% of price), an erratic candle (range above 3 times the recent median), or available volume below half its recent average. Volume feeds are not universal; when volume is unavailable, confidence is capped rather than treating missing volume as adequate. These diagnostics influence decisions but are omitted from dashboard cards. Regimes are classified as Trending, Ranging, Volatile, or Quiet. The default trend-following strategy uses a 2-of-3 timeframe alignment threshold; the optional RSI, EMA/MACD, and Bollinger/RSI strategies retain their adaptive weighted composite score of at least 0.45. Confidence reflects cross-timeframe alignment and data quality.

Stops start at 1.5 ATR and may be widened just beyond nearby recent support/resistance; targets are recalculated at 2R. Recent closed candles are also used for simplified directional backtests, with trade count, win rate, and net R calculated internally. The trend-following historical sample uses the EMA/MACD/RSI direction rule; live entries additionally require the multi-timeframe alignment above. Backtests use a maximum 12-candle holding window, treat same-candle stop/target touches conservatively as stop-outs, and exclude fees, spread, and slippage. They are informational only: thresholds remain fixed and are not auto-tuned. Diagnostic inputs such as regime, ATR, volume availability, feed verification, support/resistance reasoning, and backtest metrics inform filtering and confidence but are not displayed in the dashboard cards.

Confidence is a confluence label, not a probability or a guarantee. Browser notifications are optional and require enabling the trade-alert control in the dashboard. Dashboard scans pause when the page is closed or auto-scan is disabled; the separately configured GitHub Actions scan continues on its five-minute schedule. Alerts are advisory: the bot does not execute orders or calculate position size. The user must confirm executable broker prices, instrument contract specifications, and account-specific risk limits before acting.

Routine HOLD results are grouped into a single summary per manual scan rather than one log entry per asset. Auto-scan does not repeatedly log unchanged no-setup outcomes; individual HOLD reasons remain visible on the asset cards, while actionable signals and data-quality warnings remain in the transparency log.
